# 协议

生产者 → 悬浮窗。**单向 UDP**，无握手、无重传、无 ACK。

> v2 起生产者是进程外守护 `espd`（`process_vm_readv` 只读内存），不再是游戏进程里的 gadget 脚本。帧格式、端口、字段**一字不改**，所以悬浮窗绘制代码零改动。旧生产者见 [LEGACY-gadget.md](LEGACY-gadget.md)。

```
目标: 127.0.0.1:29000   (UDP)
发送: 每 2 帧一次（EVERY = 2）
编码: UTF-8 文本，行尾 \n
```

## 帧结构

```
FRAME
U <nx> <ny> <hp> <mx> 0 <cd> <dist> <oa>
U ...
A <nx> <ny> <ang> <vang> <spd>
END
```

- `FRAME` / `END` 是定界符，中间 0~N 行 `U` + 可选 1 行 `A`。
- 没有任何目标时也发（`FRAME\nEND\n`），用来表明脚本还活着。
- 一行一个目标，重复目标（屏幕距离 < 28px）会被脚本侧丢弃。

## `U` 行 — 敌人

| 字段 | 类型 | 含义 |
|---|---|---|
| `nx` | float 4 位 | 屏幕 X，归一化 0~1。**可能越界**（<0 或 >1 表示屏外），用来保留真实方位 |
| `ny` | float 4 位 | 屏幕 Y，归一化 0~1，原点左上。可能越界 |
| `hp` | int | 当前血量，`-1` = 未知（本版不显示） |
| `mx` | int | 最大血量，`-1` = 未知 |
| `0` | int | 保留位（旧版是血条可见性标志，现恒为 0） |
| `cd` | float 1 位 | 敌方替身剩余冷却秒数，`-1` = 不在冷却 / 未知 |
| `dist` | float 1 位 | 相机空间欧氏距离（米） |
| `oa` | int | 屏外方位角（度）。目标在屏内时为 `-999`；屏外时 = `atan2((ny-0.5)*H, (nx-0.5)*W)` |

> 不要对 `nx`/`ny` 做 clamp：所有屏外目标会压到同一个点，方位信息全丢。悬浮窗按越界坐标做「屏幕边缘指示」才对。

## `A` 行 — 自己脚下指向

| 字段 | 类型 | 含义 |
|---|---|---|
| `nx` | float 4 位 | 自己脚下在屏幕上的归一化 X |
| `ny` | float 4 位 | 自己脚下在屏幕上的归一化 Y |
| `ang` | int | 自己 → 敌人的屏幕方位角（度，0=右，顺时针）。已做 0.45 系数平滑 |
| `vang` | int | 敌人屏幕速度方向（度），`-999` = 静止/未知 |
| `spd` | float 1 位 | 敌人屏幕速度（px/帧，0.3/0.7 指数平滑） |

`ang` 的算法：

- 敌人可见：`atan2((enNy-myNy)*H, (enNx-myNx)*W)`
- 敌人屏外：把「自己相对敌人」的点投影回屏幕，再取反 +180°

## `SPLASH` 行

```
SPLASH <pid>
```

脚本初始化完成（tick 已挂上）时发一次。悬浮窗按 pid 去重，同一进程只播一次启动动画。

## 状态（不走 UDP）

v2 用 `/data/local/tmp/.esp/status.json` 取代旧的 `.dh`，**不写游戏目录**。

`espd` 每 30 帧原子写一次（先写 .tmp 再 rename，避免读到半个 JSON）：

```json
{"ts":...,"pid":...,"il2cpp":...,"frames":...,"sent":...,"errors":...,"cam":1,"pvp":1,"uptime_ms":...,"domain":"u:r:ksu:s0"}
```

- `cam=1` 相机解析/投影就绪
- `pvp=1` 已解析并绑定 `PVPStatis`
- `errors` UDP 发送累计失败数
- `domain` 必须是 `u:r:ksu:s0`；掉到 `u:r:shell:s0` 就读不到 app 内存

旧 `.dh`（`/data/user/0/com.tencent.KiHan/files/.dh`，`t=/mat=/ent=/tk=/pvp=/g=`）只在旧架构里由 gadget 写，v2 完全不碰。

## 兼容性注意

- 字段是**位置参数**，不是 key=value。加字段必须追加在末尾，且悬浮窗要先容忍多余字段。
- `cd` 的语义依赖游戏内 `enemySubstituteCurStateFlag`：`1=可用`、`0=冷却中`。`1→0` 开始计时（默认 15000ms），`0→1` 用实测间隔自校准（仅当落在 13~16s 且偏差 >300ms 时采信）。
